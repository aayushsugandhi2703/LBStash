# Infra and local running

- Root: `docker-compose.yml` is the only compose file (whole stack; `docker compose up --build`). `pyproject.toml` + `uv.lock` (uv workspace), `.env.example`. Opt-in `test` profile adds `test-db` (Postgres on 5544).
- Images: `docker/base.Dockerfile` (Python base + `bt`), `services/<name>/Dockerfile` (one per service, `ARG BASE_IMAGE`), `apps/web/Dockerfile` (Node, context `apps/web`). Names `${REGISTRY}budget-<name>:${IMAGE_TAG}`; `docker compose build && docker compose push` publishes them.
- Scripts: `scripts/gen-secrets.py` (writes `.env`), `scripts/e2e.py` (end-to-end over HTTP against a running gateway).
- Without Docker: Postgres on 127.0.0.1:5544 (user `bt_admin`, db `budget`), run `python -m bt.db.init` with `ADMIN_DATABASE_URL` and `DB_PASSWORD_*`, then start each `bt_<service>.main` with `PORT`, `SERVICE_NAME`, `DATABASE_URL`, `QUEUE_DATABASE_URL`, `INTERNAL_SECRET`, `ACCESS_TOKEN_SECRET`, `FIELD_KEY` and the `*_URL` addresses on 127.0.0.1. Use `REGISTRATION=open` and `PUBLIC_URL=http://localhost:8088` for the e2e script.
- `nginx/` is part of the main compose: `nginx` and `certbot` services start with `docker compose up -d`. Config templates (`https.conf.template` redirects http to https://$DOMAIN and proxies to `proxy:80`; `http-only.conf.template` is used until the certificate exists), `start.sh` swaps between them, `certbot.sh` requests/renews the Let's Encrypt cert into `nginx/certs`. It stays idle until `LETSENCRYPT_EMAIL` is set in `.env`; then set `PUBLIC_URL=https://<DOMAIN>`. `cloudflared` (profile `tunnel`, needs `TUNNEL_TOKEN` in `.env` + `COMPOSE_PROFILES=tunnel`) serves the domain with no open ports; nginx takes the visitor IP from `CF-Connecting-IP`. Caddy trusts the forwarded client address (`trusted_proxies` in `docker/Caddyfile`). Not run yet: needs DNS and open ports 80/443.
- Backend tests: start a scratch Postgres (`docker run -d --rm -p 127.0.0.1:55432:5432 -e POSTGRES_PASSWORD=test postgres:17-alpine`), set `TEST_DATABASE_URL=postgres://postgres:test@127.0.0.1:55432/postgres`, run `.venv/bin/python -m pytest services/<name>/tests` one service at a time. Web tests and `tsc` run in Docker: `docker build --target build -t ledger-web-check apps/web` then `docker run --rm ledger-web-check npx vitest run`.
- Migrations are forward-only files per service and run when the service starts (`auth` 002 adds `users.allowed_ips`, `telegram` 003 adds `telegram_bots.owner_tg`).
- Run e2e: `PUBLIC_URL=http://localhost:8088 GATEWAY=http://127.0.0.1:3000 .venv/bin/python scripts/e2e.py` (PUBLIC_URL must equal the stack's).
